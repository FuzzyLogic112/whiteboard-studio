# 待办与已知问题

一次代码审查的结果，按投入产出比排序。**都还没动手**——记在这里是为了把当时的
实测数据一并留下，省得以后重新查一遍。

每条都写了：问题是什么、怎么验出来的、影响、以及打算怎么改。

---

## 1. 没有 CI，154 个测试不会自动跑

**现状**：`.github/workflows/` 下只有 `pages.yml`（发布展示页）。推代码不跑测试。

**影响**：测试覆盖了分镜、分词、标注、矢量化、配图、接口契约和三个外部服务的
mock，但没有任何东西保证它们还是绿的。最容易悄悄退化的地方。

**怎么改**：加一个 `ci.yml`，push 和 PR 时跑三件事：

```bash
cd backend  && pytest
cd renderer && npx tsc --noEmit
cd web      && npm run build
```

注意 `backend` 依赖 numpy 和 Pillow（矢量化要用），要装完整依赖而不是只装 fastapi。

---

## 2. `simplify` 在长路径上会爆栈

**现状**：`vectorize.py` 里的 Ramer–Douglas–Peucker 是递归实现的。

**实测**（锯齿形折线，最坏情况）：

| 点数 | 结果 |
| --- | --- |
| 500 | OK |
| 2000 | OK |
| 6000 | `RecursionError`（Python 默认递归上限 1000） |

**影响**：密集或带纹理的生图会产生很长的骨架链。触发时 `RecursionError` 会一路
冒到任务执行器，**整个任务失败**，而不是像其它配图错误那样退回内置简笔画。

**怎么改**：把递归改成显式栈的迭代实现（RDP 很容易改）。顺带在
`illustrate/glm_image.py` 里把 `RecursionError` 也归入可兜底的错误。

---

## 3. 分镜数量没有上限，可能误烧钱

**现状**：文稿上限是 20000 字符（`CreateJobRequest.text`），但对切出多少个分镜
没有任何限制。

**实测**：20000 字符能切出 **400 个分镜**。这意味着——

- 开 `glm_image` 配图 = **400 次生图调用**，每次都按张收费
- 成片约 **17 分钟**，渲染要几小时
- 界面上**没有任何提示或确认**

**影响**：用户粘贴一篇长文，点下去就是一笔预料之外的账单。

**怎么改**：

- `/api/preview` 返回里加上分镜数、预估时长、以及（配图器为 AI 时）预计的生图
  次数；前端在按钮旁边显示
- 加一个可配置的分镜数上限（默认比如 120 镜），超了返回 400 并说明
- 超过某个阈值时前端要求二次确认

---

## 4. 任务目录无限增长

**现状**：`jobs.py` 里没有任何清理逻辑。每个任务在 `.workspace/jobs/<id>/` 下
留一个 `output.mp4`（17 秒的约 1.4MB）、`plan.json`、以及配了 TTS 时的
`audio/*.wav`。

**影响**：跑一百次就是 GB 级，而且服务重启时 `JobStore._load_existing` 会把它们
全部读回内存。

**怎么改**：加保留策略——按数量（保留最近 N 个）或按时间（超过 N 天删掉），
启动时和每次任务完成后各清一次。注意别删掉正在跑的任务。

---

## 5. 接口完全没有鉴权

**现状**：`main.py` 里没有任何 `Depends` / token 校验。

**影响**：**只在部署到公网时才是问题**——本机自己用无所谓。一旦暴露出去，任何人
都能触发渲染，烧掉 CPU 和你的 GLM / 生图额度。

**怎么改**：加一个可选的 Bearer token（比如 `WBS_API_TOKEN`），不设就不校验——
和 `tools/indextts_server.py` 里已经用的是同一套做法，可以照抄。

---

## 6. 前端只用了 9 个接口里的 4 个

**现状**：前端用了 `/api/health`、`/api/concepts`、`/api/preview`、`/api/jobs`。
没用的有：

| 接口 | 本来能做什么 |
| --- | --- |
| `GET /api/jobs` | 任务历史列表（现在刷新页面就丢了） |
| `GET /api/jobs/{id}/log` | **降级原因就写在这里**——标注退回本地、配图退回内置、语音失败，全都记在任务日志里 |
| `GET /api/jobs/{id}/plan` | 完整渲染计划，调试用 |

**影响**：第二条最要紧。整个项目的降级策略是「可以兜底，但必须留痕」，而**留下的
痕迹用户在界面上看不到**——只能去翻 curl。这等于把设计意图落实了一半。

**怎么改**：任务面板加一个可展开的日志区；历史任务列表放在页面底部。

---

## 不打算改的

- **中文关键词是擦除动画，不是真笔顺**——真笔顺需要汉字笔画数据集（如
  Make Me a Hanzi），那是另一个量级的工程，不在这个项目的范围里。
- **中心线矢量化表示不了实心色块**——这是方法本身的性质，不是 bug。质量闸门
  已经把这类图挡在外面了。
