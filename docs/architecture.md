# 设计说明

记录几个「为什么这么做」的决定，省得后来的人重新踩一遍。

## 时长由语音决定，不是由画面决定

`TTSProvider.synthesize` 返回时长，整条流水线的时间基准都来自它：分镜多长、
笔迹画多快、字幕停多久。这样接上真实的声音克隆之后，画面自动跟着新的语速走，
不需要再调一遍节奏参数。

默认的 `silent` provider 不产音频，只按 4.5 字/秒估算——这个数字来自中文口播的
经验语速。它的存在是为了让「装完依赖就能出片」成立：先把画面和节奏调对，
再决定要不要接模型。

## 笔迹用 stroke-dashoffset，不用逐帧重绘

一条 SVG path 设 `stroke-dasharray = 全长`，再把 `stroke-dashoffset` 从全长退到 0，
视觉上就是线条从起点长出来。浏览器原生支持，成本几乎为零。

代价是需要知道 path 的精确长度，只有 `getTotalLength()` 给得出，而它要求 DOM
已经挂载。所以 `DrawnPath` 用 Remotion 的 `delayRender` / `continueRender` 卡住
第一帧，量完再放行。

## 笔尖位置一次采样，不逐帧查询

马克笔要跟着笔迹走，直觉做法是每帧调 `getPointAtLength(当前长度)`。但渲染时
每一帧都是一次独立的 React 提交，逐帧读 DOM 会在首帧拿不到值而抖动。

改成挂载时一次性采样 160 个点存进 state，之后每帧只是查表。结果稳定，而且
同一份 plan 重渲染的结果完全一致——这对「改一个字重渲一遍对比」很重要。

## 每一笔的时间片按长度分配

等分时间片会让一条长曲线唰地一下画完、一个小圆点却磨蹭半天，非常出戏。
`sketch._rough_length` 把 path 里的坐标当折线顶点粗估长度，按比例分配时间。

它不解析贝塞尔曲线，所以不是真实弧长——但这里只用来分时间片，量级对就够了。

## 中文关键词是擦除，不是书写

英文可以用单线字体描出笔顺，中文不行：真要按笔顺写出来需要汉字笔画数据集
（比如 Make Me a Hanzi），那是另一个量级的工程。

折中方案是 `clip-path: inset()` 从左到右揭开。节奏上仍然像「一个字一个字写出来」，
而且文字是真实文本节点——OCR 和字幕提取都读得到，不会变成一张图。

## 分词的取舍

`keywords.py` 没用 jieba：它的 setup.py 太老，在新版 pip 下经常构建失败
（本项目初次搭建时就撞上了），而这里只需要从一句话里挑一个能画的词。

现在的做法是把虚词当切分点，对剩下的片段按「字数 × 全文词频 × 是否在别处
独立成段」打分。第三项是个便宜的信号：如果「写作」在文稿别处正好被虚词夹成
一个完整片段，它多半真是个词。

已知的坑都写成了测试：
- 「能」不能当虚词，否则「人工智能」会被切成「人工智」；
- 「能进步」这类半截短语要靠 `_BAD_HEAD` 压下去，让「进步」胜出。

## 任务状态落盘

白板动画渲一次要好几分钟，进程重启就丢是不能接受的。每个任务在
`.workspace/jobs/<id>/state.json` 里有自己的状态，重启后能读回历史任务和
已经渲好的成片。

没跑完的任务不会自动续跑——会被标成「服务重启，任务已中断」。比一直显示
「渲染中」诚实。

## 语音合成失败要吵，不要静音

`SilentFallback` 是可选包装，默认**不**启用。

理由是失败模式的分布：配错服务地址、写错音色名、忘了下模型，比「模型偶发抽风」
常见得多。这些情况下退回静音，用户会拿到一条渲染成功、但没有声音的片子——
往往要等几分钟渲染跑完、点开播放才发现不对，然后还得回头猜是哪一步出的问题。

直接失败并把原因写进任务状态要好得多。`/api/health` 还会预先验一遍配置，
前端顶部直接显示，连渲染都不用等。

需要「宁可没声音也别中断长任务」的场景，`WBS_TTS_FALLBACK_SILENT=1` 显式打开。

## 为什么固定要 wav

时长是整条流水线的时间基准，必须精确。wav 读个文件头就知道时长；mp3 得解码。

所以 HTTP provider 固定发 `response_format: "wav"`，拿到非 wav 直接报错，
而不是退回字数估算——退回去的话字幕会和声音越走越偏，而且很难察觉。
