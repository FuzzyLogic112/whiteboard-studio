# 配图：内置简笔画 与 AI 生图

| 配图器 | 怎么工作 | 需要什么 |
| --- | --- | --- |
| `builtin`（默认） | 32 个内置简笔画 + 关键词哈希涂鸦兜底 | 无 |
| `glm_image` | 智谱生图 → 中心线矢量化 | 智谱 API key |

```bash
export WBS_ILLUSTRATOR=glm_image
export WBS_IMAGE_MODEL=cogview-3-flash      # 免费；换 glm-image 质量更好
export WBS_IMAGE_WATERMARK=0                # 见下方「水印」
```

## 为什么必须矢量化

生图模型返回的是**位图**。白板动画的全部观感来自 `stroke-dashoffset` 让线条
从起点长出来——位图做不到这件事，直接贴上去淡入就退化成幻灯片了。

所以拿到图之后要过一遍 `vectorize.py`：

```
灰度 → Otsu 二值化 → Zhang-Suen 细化 → 骨架图遍历 → RDP 简化 → 贝塞尔平滑
```

**取中心线，不取轮廓。** potrace 那一类工具描的是色块**轮廓**：一条 3 像素宽的
线会变成绕着它跑一圈的闭合环，动画播出来是「沿着线画过去、再沿另一侧画回来」，
明显不像手写。细化成 1 像素骨架之后，笔尖轨迹就是真正的中心线，画一次就完事。

只依赖 numpy 和 Pillow，没有 OpenCV / potrace。

## 提示词是调出来的

`PROMPT_TEMPLATE` 里那几条约束都有实测教训：

- **不写「禁止阴影、投影、立体感」**，模型会给简笔画加投影。双线轮廓细化之后
  会碎成一段段弧，笔顺就乱了——实测一个齿轮从 17 笔碎成 24 笔，同心圆断成
  多截。
- **不写「主体居中、四周留白」**，主体容易顶边，归一化之后构图很挤。
- **不写「一种粗细均匀的黑色细线」**，会出现粗细变化和灰度过渡，二值化之后
  边缘毛糙。

## 水印

智谱默认给生成图加右下角的「AI生成」显式水印。对我们是硬伤——**矢量化会把水印
也当成笔迹描出来**，然后一笔一笔画在白板上。

关掉需要先在控制台签署免责声明：**个人中心 → 安全管理 → 去水印管理**。
签完传 `watermark_enabled: false` 才生效。

⚠️ **没签之前这个参数会被静默忽略**：接口返回 200、不报错，水印照加。所以别看
响应就当成功了，要看图。

没签也能用：`WBS_IMAGE_WATERMARK=1`（默认）时会自动**裁掉图片底部 10%**。
水印固定在右下角、占 17.9% 宽 × 7.9% 高，裁掉不影响居中的主体。

## 型号与限流

文档列出的型号是 `glm-image` / `cogview-4` / `cogview-4-250304` / `cogview-3-flash`，
但**能不能用取决于账号**。实测某个账号上 `glm-image` 一直返回 502 或
`1302 速率限制`，即便单独打、间隔很久也一样；`cogview-4` 则正常。

换型号之前先单独 `curl` 一次确认可用，别直接跑整篇渲染。

**逐镜连续生图必然撞账号级速率限制。** 智谱返回 429（`code 1302`），上游偶尔
还会 502。所以 408/429/5xx 和连接超时都会退避重试（4s → 12s → 30s），
重试次数用尽才退回内置简笔画。不重试的话，一篇二十镜的稿子基本上必然有几镜
掉进兜底——第一次跑 `glm-image` 就是四镜全军覆没。

400 之类的错误不重试：那是提示词或参数写错了，重试多少次都一样。

## 缓存

生成一张图几秒到几十秒，而且按张收费。结果按提示词哈希缓存在
`.workspace/cache/illustrations/`，同一个关键词重渲不会再花钱，换模型、换尺寸、
改水印开关都会换一个缓存键。

**一镜一张图**：20 个分镜的文稿第一次跑会生成 20 张。先用 `/api/preview` 把分镜
调好再渲染，能省不少。

## 失败了会怎样

**自动退回内置简笔画，并把原因写进任务日志。** 和标注器同一个策略：配图失败
只是「图没那么贴切」，片子仍然完整。

最常见的失败是**图片下载不了**：图片托管在与 API 不同的域名上（对象存储），
只放行 API 域名的话，接口会正常返回 URL、下载却 403。报错信息里专门写了这一点。

## 质量闸门：不好的图直接退回内置简笔画

生图模型经常无视「线稿」约束，输出照片、实心色块或带纹理的 3D 渲染。这些东西
中心线法表示不了，硬转出来是一团认不出的乱线——**比画一个规规矩矩的内置图形
差得多**。

所以矢量化之后有两道闸门，指标是照着实测数据定的：

| | 墨迹占比 | 骨架/墨迹 |
| --- | --- | --- |
| 干净线稿（锤子、铅笔） | 0.01 ~ 0.05 | **0.30 ~ 0.45** |
| 实心五角星 | 0.048 | **0.082** |
| 实拍照片 | 0.28 ~ 0.39 | 0.04 ~ 0.15 |
| 阈值 | > 0.15 拒绝 | < 0.20 拒绝 |

「骨架/墨迹」是关键指标：细线细化后大约剩 1/线宽（0.3~0.5），实心色块会塌成
一条脊线，比值极低。这一条能抓住墨迹占比看不出来的实心图形。

被拒绝的结果**不写进缓存**，换个提示词重试还能再要一次。

## 实际能用到什么程度

诚实的结论：**大约一半。** 同一段文稿的四镜实测——

| 视觉隐喻 | 生成结果 | 结局 |
| --- | --- | --- |
| 一把锤子 | 干净线稿 | ✅ 5 笔，很好 |
| 一支铅笔 | 干净线稿 | ✅ 14 笔，很好 |
| 一颗星星 | 实心黑星 | ❌ 闸门拒绝，退回内置 |
| 一座积木塔 | 带砖块纹理 | ⚠️ 过了闸门但笔迹很碎 |

闸门保证了**不会输出一团乱线**，但也意味着有一部分镜头拿不到 AI 配图。
内置简笔画在稳定性上仍然更强——`glm_image` 适合「愿意多花一点钱换点变化」的
场景，不适合当成默认。

## 已知限制

- **实心色块会被细化成骨架线**。灯泡那个纯黑的灯头，中心线法只会留下一条脊线。
  白板风格下这其实不难看，但和原图不一样。
- **交叉点会把笔画拆开**。T 形交叉处一笔变三笔，笔顺因此变碎。
- **图越复杂越不稳**。带阴影、渐变、纹理的图矢量化出来会很乱，所以提示词把这些
  都禁掉了；即便如此，模型偶尔还是会加。分镜可编辑那一层在这里同样有用——
  某一镜的图不理想，直接换成内置概念。
