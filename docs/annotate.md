# 分镜标注：挑关键词 + 选简笔画

「这一镜写哪个词」和「配哪张图」本质是同一个判断——看懂这句话在讲什么。
所以这两件事由同一个标注器负责。

| 标注器 | 怎么工作 | 需要什么 |
| --- | --- | --- |
| `local`（默认） | 分词打分挑词 + 触发词匹配选图 | 无 |
| `glm` | 智谱 GLM 一次请求标注全篇 | 智谱 API key |

## local

见 [architecture.md](./architecture.md) 里「从猜词边界到真分词」几节。
不需要任何外部服务，装完依赖就能用。

天花板在于：**简笔画靠触发词命中**。概念表再长也穷举不完所有说法，命不中就
只能画兜底涂鸦。

## glm

```bash
export WBS_ANNOTATOR=glm
export WBS_GLM_API_KEY=你的key        # 见下方「云环境里可以不填」
```

一次请求把整篇的分镜都标注完，而不是逐句调用——模型能看到上下文，才知道哪个
词是全篇主题、哪一镜该换张图。

比 local 强的地方是**按语义选图**：概念表整个发给模型，它自己判断哪张最贴切，
不依赖触发词命中。同一段文稿的实测对比：

| 分镜 | local | glm |
| --- | --- | --- |
| 很多人以为写作是天赋。 | 天赋 · `doc` | 天赋 · `person` |
| 其实写作是一门可以练习的手艺。 | 手艺 · `doc`（和上一镜重复） | 手艺 · `edit` |
| 选题决定了上限， | 选题 · `fork` | 选题 · `idea` |
| 结构决定了下限， | 结构 · `stack` | 结构 · `gear` |
| 修改决定了成品。 | 成品 · `edit` | 修改 · `edit` |
| 今天我们把这三件事聊清楚。 | 三件事 · **`doodle`** | 聊清楚 · `chat` |

涂鸦从 1 镜降到 0，相邻重复也消失了。关键词质量互有胜负——`local` 的「三件事」
就比 `glm` 的「聊清楚」好。这也是[分镜可编辑](../README.md)存在的意义。

### 云环境里可以不填 key

在 Claude Code 的云环境里，把 key 存成环境的 **API credential**（限定 host 为
`open.bigmodel.cn`），代理会在请求**离开沙箱之后**补上 `Authorization` 头。
key 不进本进程、不进环境变量、也不进对话记录。

所以 `WBS_GLM_API_KEY` 是可选的：没配就不带这个头，让代理去补。

### 模型选择

默认 `glm-4-flash-250414`：免费、稳定、返回干净的 JSON。想要更好的效果可以换成
`glm-4.6` 之类，改 `WBS_GLM_MODEL` 即可。

注意有些型号会返回带思考过程的内容，或者时不时报「访问量过大」——换模型之后
建议先跑一遍 `/api/preview` 确认输出正常。

## 失败了会怎样

**自动退回 local，并把原因写进任务日志。**

这和语音合成的策略**故意不一样**：TTS 失败退回静音，交付的是一条没声音的片子
——残缺的成品，所以默认直接报错。标注失败退回 local 只是「词挑得没那么好」，
片子仍然完整，自动兜底更划算。

但兜底不是悄悄降级，原因会出现在 `GET /api/jobs/{id}/log` 里：

```
glm 标注失败，本次改用本地结果：GLM 返回 429：{"error":{"code":"1305",...}}
```

模型只答对一部分时也一样：无效的位置用 local 补齐，并记一条
`glm 有 2/6 镜的结果无效，已用本地结果补齐`。

## 模型输出是不可信的

`glm.py` 里的 `_parse` 对返回结果逐项校验：

- 编造出来的 concept（不在概念表里）→ 丢弃，留空由 local 补
- 越界或非整数的 index → 忽略
- 超长的关键词 → 截断到 4 字
- 少给的分镜 → 用 local 补齐

**拿不准的位置留空、不整批失败**，因为模型八成是对的，为了一镜错就退回全部
local 太浪费。这些行为都钉了测试（`tests/test_annotate.py`，对着 mock 服务跑，
不打真实接口）。

## 自己写标注器

实现 `pipeline/annotate/base.py` 里的 `Annotator`（一个
`annotate(sentences) -> List[SceneAnnotation]`），在
`pipeline/annotate/__init__.py` 的 `build_annotator` 里加分支。失败请抛
`AnnotationError`。
